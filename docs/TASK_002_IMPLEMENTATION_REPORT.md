## ما أضيف

- دورة مستقلة لدفعات الرجوع مرتبطة بالمهمة EJ الأصلية وبندها ورولتها، دون إنشاء EJ عند الاستلام. رقم ورقة المصبغة مستقل، مع تاريخ الاستلام والمستخدم والملاحظات وروابط المرفقات.
- خدمة افتراضية من نوع تجهيز المهمة عند الإرسال، وإمكانية إضافة عدة خدمات وكمياتها قبل بدء الرجعات أو التسعير. ربط الخدمات المكتملة بالدفعة دون إنشاء مخزون عن كل خدمة.
- حفظ لقطة بيانات الإرسال للمهام الجديدة: الخامة والمستودع والبكرة والأمتار والباركود واللون والوزن والتكلفة والعملة والعرض والوزن النوعي.
- استلام جزئي ومتعدد، والتحقق التراكمي من المتبقي لكل بند، وتسويات نقص أو زيادة معتمدة. الزيادة تحتاج اعتماداً مسبقاً قبل إدخالها. لا تغلق المهمة مع فرق مفتوح أو عيب بلا قرار.
- كل رولة/جزء واصل ينشئ رولة مخزون وحركة رجوع واحدة داخل معاملة الدفعة نفسها. لا تتكرر الحركة بسبب الخدمات المتعددة. الجزء السليم والمعيب يسجلان في بندين منفصلين تحت مستند الرجعة نفسه.
- مفتاح طلب فريد وبصمة محتوى وقفل استشاري وقفل المهمة والرولات لمنع تكرار الاستلام وتجاوز المتبقي عند التزامن. تعاد نفس الدفعة للطلب نفسه؛ اختلاف محتوى المفتاح يرفض.
- البضاعة المعيبة تدخل المخزون فعلياً بحالة RESERVED للفحص، مع سبب العيب والجهة المسؤولة. قبولها يجعلها AVAILABLE؛ إعادة التشغيل تجعلها DAMAGED حتى إرسال مرحلة مرتبطة ومصرح بها؛ الشطب يجعلها INACTIVE. يحتفظ السجل بالقرار والمستخدم والتاريخ والسبب.
- حماية خلفية للبيع والمناقلة والنقل المباشر، وحاجز قاعدة بيانات يمنع استهلاك الرولة المحجوزة أو تحريرها أو تغيير موقعها من المسارات القديمة. يستبعد onlyAvailable حجز الفحص تحديداً، ويبقى سلوك RESERVED العادي كما كان.
- خيار مستقل «استلام من مصنعية خارجية» في شاشة بدء عملية الإدخال، مع البحث ومسح EJ واختيار المهمة. نموذج الرجعة داخل مسار صفحة إدخال المادة يعرض البنود الأصلية ويسجل الكميات والأوزان واللون والباركود والأبعاد الفعلية دون استدعاء إنشاء مخزون عام منفصل.
- تبويب «تسعير المصنعية / فاتورة المصنعية»: تسعير مستقل لكل خدمة بالمتر أو الكيلو أو مبلغ مقطوع، والعملة والكمية المعتمدة والإجمالي. تجمع القيم بالدولار بسعر الصرف القائم في fee_amount الحالي، ويستخدم ترحيل أجرة المهمة الموجود إلى مصروف المصنعية وذمة المورد. لم ينشأ نظام قيود موازٍ أو فاتورة مشتريات مخزنية إضافية. يمنع تعديل السعر بعد الترحيل وترحيل الأجرة مرتين عبر القفل وفحص الحالة الموجودين.
- قائمة المهمات تعرض المرسل والمستلم والمتبقي والتجهيز والفروقات وحالة الأجرة والترحيل، والتفاصيل تعرض الرجعات والعيوب والتسويات والخدمات ومراحل التشغيل.

## الترحيلة

`079_external_manufacturing_lifecycle.sql` إضافية ومستقلة عن 078. آخر ترحيلة على clotex عند جلب الأساس هي 077؛ ترك الرقم 078 محجوزاً لترحيلة TASK 001 المنشورة في PR #2. يلزم إعادة فحص الترقيم قبل الدمج إذا أضيفت ترحيلات لاحقاً.

الترحيلة تنشئ جداول الخدمات ودفعات الرجوع وبنودها وربط الخدمات والتسويات، وتضيف حقول اللقطات والمرحلة السابقة والإغلاق، وحواجز حجز الفحص. لا تحذف أو تعيد كتابة بيانات سابقة، ولا تسقط قيد الاستلام القديم الوحيد؛ يبقى المسار القديم محفوظاً ولا يخلط بالدفعات الجديدة.

لم تشغل الترحيلة أو أي قاعدة بيانات. توافقها مبني على قراءة الترحيلات والمخطط في المصدر فقط؛ نجاح تطبيقها وأثر الأقفال والفهارس يلزمان اختبار نبيل على نسخة تجريبية.

1. `server/src/routes/fabricRollRoutes.ts`: شرط AVAILABLE فقط في النقل المباشر، واستبعاد حجز الفحص من onlyAvailable. يجب دمج استبعاد حجز الفحص مع تنفيذ نقل TASK 001، وعدم استبدال إصلاحاتها أو إرجاع RESERVED العادي إلى سلوك مختلف.
2. `server/src/routes/inventoryTransferRoutes.ts`: تعديل شرط أهلية التأكيد ورسالة الخطأ فقط. TASK 001 تعيد بناء هذا المسار؛ عند الدمج تستخدم خدمتها المعاملية وتبقى أهلية AVAILABLE وحماية الفحص.

4. المصنعية وخدمة البيع تغيرتا فقط لإضافة دورة الرجعات وحماية حجز الفحص. لم يتغير نظام توثيق الجلسات أو تبديل الشركات، وتستخدم المسارات companyId من الجلسة لا من جسم الطلب.

هذه الحماية لا تعتمد على دمج TASK 001. أخطاء المناقلات الأخرى في clotex الأساسي ليست إصلاحاً ضمن TASK 002؛ لا تسحب TASK 001 إلى هذا الفرع لتجاوزها.

## حدود التصميم والمراجعة المطلوبة

- الاستلامات القديمة المقيدة باستلام إجمالي واحد أو استلام بنود قديمة تبقى ظاهرة ومحفوظة. لا تحول تلقائياً إلى دفعات ذات ربط بالبكرات، لأن بيانات المطابقة غير موجودة؛ يلزم تحويل يدوي معتمد إن أريد استكمالها بالدورة الجديدة.
- الرولات الناتجة من الدفعات لها باركود فريد جديد (مولد أو مدخل) مع حفظ الباركود الأصلي وعلاقة المصدر. لا يعاد استخدام باركود الرولة الأصلية الموجودة، لتجنب تصادم هوية الأجزاء والدفعات.
- الرولات الأصلية تبقى AT_EXTERNAL_JOB بكمية الباقي الفعلي فقط؛ تنقص أمتارها وأوزانها المتبقية مع كل رجعة/نقص معتمد، مع حركة تسوية موثقة ولقطة إرسال ثابتة، لمنع جمع الأصل كاملاً مع الرجعات. تصبح INACTIVE بكمية صفر عند الإغلاق، مع حركة حالة للتوثيق. الزيادة المعتمدة لا تضيف مخزوناً حتى تصل فعلياً. يجب التحقق من تقارير الرصيد لجميع الحالات، لا من AVAILABLE وحده.
- المرفقات مدعومة كروابط HTTPS أو روابط uploads قائمة؛ لم يضف رفع ملفات أو تخزين صور جديد.
- الحقول الجديدة عربية؛ لم تترجم الإضافات الجديدة إلى التركية. الوظائف والترجمات القائمة لم تحذف.
- قرارات الشطب وتسوية النقص تسجل مخزونياً/تشغيلياً فقط؛ لم يخترع قيد خسائر محاسبي. يراجع نبيل والمحاسب سياسة تقييم الفاقد والعيوب وتكلفة المرتجع (الموروثة من رولة الإرسال) قبل اعتماد الإنتاج.
- لم ينشأ مستند فاتورة مشتريات جديد أو رقم فاتورة قانوني؛ «ترحيل فاتورة المصنعية» يستخدم ترحيل الأجرة الموجود على المهمة. إذا كان المطلوب فاتورة مستقلة مرقمة/ضريبية فذلك يحتاج اعتماد تصميم إضافي.
- لا تعتبر النسخة جاهزة للإنتاج قبل الفحوص المذكورة أدناه، ولا يوجد تأكيد بخلو وظائف ERP الأخرى من التأثيرات دون تشغيلها.
